# Build Sentinel File

**Date:** 2026-04-04
**Status:** Approved
**Addresses:** REVIEW.md HIGH: `build --force` can delete the source tree

## Problem

`guardOutputDir()` calls `os.RemoveAll(b.Output)` when `--force` is set, with no check that the
output directory was actually created by a previous build. Running `gomddoc build . -o .` deletes the
entire source tree.

## Solution

Replace the `--force` flag with a sentinel file (`.gomddoc-build`) that marks directories created by
`gomddoc build`. The sentinel acts as proof of ownership -- `guardOutputDir()` only deletes a
non-empty output directory if the sentinel is present.

## Behavior

`guardOutputDir()` logic:

1. Output dir **doesn't exist** -- proceed
2. Output dir **exists but is empty** -- proceed
3. Output dir **exists, not empty, sentinel present** -- `RemoveAll` and proceed (re-create sentinel
   after)
4. Output dir **exists, not empty, no sentinel** -- error: "directory is not empty and was not created
   by gomddoc build; refusing to overwrite"

After `guardOutputDir()` passes, `Run()` creates the output directory (if needed) and writes the
sentinel file before any build work begins.

## Details

- Sentinel file: `.gomddoc-build` at the root of the output directory
- Sentinel content: `"generated by gomddoc build\n"`
- Written once at the start of `Run()`, survives the build
- Present for subsequent runs to detect a previous build

## Removals

- `Force bool` field from `BuildCmd` struct
- `-f` / `--force` CLI flag
- `GOMDDOC_BUILD_FORCE` env var

## Files Changed

- `cmd/gomddoc/build.go` -- `guardOutputDir()` rewritten, `Force` field removed, sentinel write added
  to `Run()`
- `cmd/gomddoc/build_test.go` -- existing `TestGuardOutputDir` cases adapted, new cases added:
  - Non-empty dir without sentinel -> error
  - Non-empty dir with sentinel -> `RemoveAll` + success
  - Sentinel file exists after build
  - Empty dir without sentinel -> success

## Out of Scope

- Path traversal guard in `writeOutputFile` (separate issue)
- Protecting against dangerous paths like `-o /` (user error)
