# Site Configuration Specification

## Overview

A site is a collection of markdown files that gomddoc is able to load, transform to html from a theme templates and
serve as http. When the main command is called, gomddoc loads the markdown files defined by the -d parameter (`.` by
default). We want to be able to configure a site from a .gomddoc/ folder at the root of this path.

**Directory structure example**

```
rootdir/              <-- rootdir of the site as set by the -d parameter
├── .gomddoc/         <-- gomddoc config and asset override directory (optional)
│   ├── config.yml    <-- configuration file in YAML format
│   └── assets/       <-- custom assets that overlay embedded assets
│       └── themes/
│           └── custom/
│               └── layout.html.tmpl
└── README.md         <-- content file that will be served by http
```

When running `gomddoc -d rootdir`, the process should:

- Initialize
- Look for a `.gomddoc/` folder, and if it exists:
  - Look for `config.yml`, parse and initialize a website configuration struct
  - Look for an `assets/` subfolder and overlay it on top of the default embedded assets folder
- If `.gomddoc/` folder doesn't exist, use default configuration
- Apply environment variable overrides to configuration
- Block HTTP access to `.gomddoc/` path (security requirement)

The `.gomddoc/` folder should **never** be exposed over HTTP.

## Quick Reference

**Usage examples**:

```bash
# Production mode with config file (title defaults to "Docs")
gomddoc -d ./docs

# Development mode with hot reload (title defaults to "Docs")
gomddoc -d ./docs -dev

# Default title from current directory (if -d not specified, defaults to ".")
gomddoc  # Title will be capitalized basename of current directory

# Override application config via environment variables
GOMDDOC_PORT=":9000" GOMDDOC_DIR="/var/docs" gomddoc

# Override site config via environment variables (overrides default title)
GOMDDOC_META_TITLE="My Docs" GOMDDOC_THEME_NAME="dark" gomddoc -d ./docs

# Mix of CLI flags (highest priority) and env vars
GOMDDOC_PORT=":9000" gomddoc -p :8080 -d ./docs  # Uses :8080 (flag wins)
```

**Environment variable naming**:

- Built automatically from struct tags using reflection
- **Application config**: `GOMDDOC_<FIELD>` (flat structure)
  - `GOMDDOC_PORT` → `Config.Port`
  - `GOMDDOC_DIR` → `Config.Dir`
  - `GOMDDOC_DEV_MODE` → `Config.DevMode`
- **Site config**: `GOMDDOC_<SECTION>_<FIELD>` (nested structure)
  - `GOMDDOC_META_TITLE` → `SiteConfig.Meta.Title`
  - `GOMDDOC_META_DOMAIN` → `SiteConfig.Meta.Domain`
  - `GOMDDOC_THEME_NAME` → `SiteConfig.Theme.Name`

**Configuration precedence**:

```
Application Config: CLI flags > Environment Variables > Defaults
Site Config:        Environment Variables > YAML (.gomddoc/config.yml) > Defaults
```

**Asset precedence** (overlay filesystem):

```
.gomddoc/assets/ > Embedded assets
```

Example: `.gomddoc/assets/themes/custom/layout.html.tmpl` overrides embedded `assets/themes/custom/layout.html.tmpl`

## Configuration Architecture

The configuration system separates **application configuration** (runtime/operational) from **site configuration**
(content/presentation):

```
┌─────────────────────────────────────────────────────────────────┐
│                        Configuration System                     │
├─────────────────────────────┬───────────────────────────────────┤
│  Config (Application)       │  SiteConfig (Site)                │
├─────────────────────────────┼───────────────────────────────────┤
│ • DefaultIndex              │ • Meta.Title                      │
│ • Dir                       │ • Meta.Domain                     │
│ • Port                      │ • Meta.Description                │
│ • ShutdownTimeout           │ • Theme.Name                      │
│ • DevMode                   │                                   │
├─────────────────────────────┼───────────────────────────────────┤
│ Configured by: CLI flags    │ Configured by: .gomddoc/config.yml│
│                             │                + env vars         │
├─────────────────────────────┼───────────────────────────────────┤
│ Exposed to templates: ❌ NO │ Exposed to templates: ✅ YES      │
├─────────────────────────────┼───────────────────────────────────┤
│ Purpose: Server operation   │ Purpose: Site presentation        │
└─────────────────────────────┴───────────────────────────────────┘
```

### 1. Application Config (Private)

Runtime and operational settings, **NOT exposed to templates**:

```go
type Config struct {
    // Operational fields (not configurable via .gomddoc/config.yml)
    DefaultIndex    string        // Default index file (e.g., "README.md")
    Dir             string        // Root directory for content
    Port            string        // HTTP server port
    ShutdownTimeout time.Duration // Graceful shutdown timeout
    DevMode         bool          // Development mode flag (-dev)

    // Reference to site configuration
    Site *SiteConfig  // This is what gets exposed to templates
}
```

**Purpose**: Server configuration, deployment settings, operational parameters.

**Not configurable via**: `.gomddoc/config.yml` or environment variables (except via CLI flags).

---

### 2. Site Config (Public)

User-facing site configuration, **exposed to templates**:

```go
type SiteConfig struct {
    Meta  MetaSection  `env:"META" yaml:"meta"`
    Theme ThemeSection `env:"THEME" yaml:"theme"`
}

type MetaSection struct {
    Domain      string `env:"DOMAIN" yaml:"domain"`
    Title       string `env:"TITLE" yaml:"title"`
    Description string `env:"DESCRIPTION" yaml:"description"`
}

type ThemeSection struct {
    Name string `env:"NAME" yaml:"name"`
}
```

**Purpose**: Site presentation, branding, theme selection.

**Configurable via**: `.gomddoc/config.yml` + environment variables.

**YAML format** (`.gomddoc/config.yml`):

```yaml
meta:
  domain: example.com # The primary domain name for the site
  title: "Title of the website" # Site title used in templates
  description: "Meta Description" # Meta description for SEO

theme:
  name: "default" # Name of the theme to load from assets/themes/ folder
```

### Configuration Defaults

If no configuration file exists or fields are missing:

```yaml
meta:
  domain: "" # Empty string (optional field)
  title: "<basename>" # Defaults to capitalized basename of the directory specified by -d flag
  description: "" # Empty string (optional field)

theme:
  name: "default" # Always defaults to "default" theme
```

**Title Default Behavior**:

- Compute the absolute path of the directory specified by `-d` flag (using `filepath.Abs()`)
- Extract the basename (using `filepath.Base()`)
- Capitalize the first letter (using `strings.ToUpper()` on first rune)
- Examples:
  - `-d .` in `/home/user/myproject` → Title: `"Myproject"`
  - `-d ./docs` → Title: `"Docs"`
  - `-d /var/www/api-docs` → Title: `"Api-docs"`
  - `-d ~/website` → Title: basename of resolved home path, capitalized

### Separation of Concerns

| Aspect                   | Application Config (`Config`)   | Site Config (`SiteConfig`)       |
| ------------------------ | ------------------------------- | -------------------------------- |
| **Purpose**              | Runtime/operational             | Content/presentation             |
| **Configured by**        | Env vars + CLI flags (CLI wins) | `.gomddoc/config.yml` + env vars |
| **Exposed to templates** | ❌ No                           | ✅ Yes                           |
| **Examples**             | Port, Dir, DevMode              | Title, Theme, Domain             |
| **Security**             | Private (server internals)      | Public (user-facing)             |
| **Precedence**           | CLI flags > Env vars > Defaults | Env vars > YAML > Defaults       |

### Configuration Loading Behavior

1. **File Discovery**:
   - Only search for `.gomddoc/config.yml` (not `config.yaml` or extensionless `config`)
   - File is loaded into `SiteConfig` struct
   - Missing config file is **not an error** - use defaults
   - Invalid YAML syntax **is an error** - log and exit with non-zero status

2. **Field Handling**:
   - Missing fields in YAML use defaults from `NewSiteConfig()`
   - Empty string values are valid (e.g., `title: ""` is allowed)
   - Unknown fields in YAML are **ignored with a warning log**

3. **Environment Variable Overrides**:
   - Both `Config` and `SiteConfig` fields are overridable via environment variables
   - Naming convention: `GOMDDOC_<FIELD>` for Config, `GOMDDOC_<SECTION>_<FIELD>` for SiteConfig
   - **Application Config** examples (flat structure):
     - `GOMDDOC_PORT=":9000"` → `Config.Port`
     - `GOMDDOC_DIR="/var/docs"` → `Config.Dir`
     - `GOMDDOC_DEV_MODE="true"` → `Config.DevMode`
     - `GOMDDOC_DEFAULT_INDEX="index.md"` → `Config.DefaultIndex`
     - `GOMDDOC_SHUTDOWN_TIMEOUT="5s"` → `Config.ShutdownTimeout`
   - **Site Config** examples (nested structure):
     - `GOMDDOC_META_TITLE="My Site"` → `SiteConfig.Meta.Title`
     - `GOMDDOC_META_DOMAIN="example.com"` → `SiteConfig.Meta.Domain`
     - `GOMDDOC_META_DESCRIPTION="Desc"` → `SiteConfig.Meta.Description`
     - `GOMDDOC_THEME_NAME="custom"` → `SiteConfig.Theme.Name`

4. **Precedence (highest to lowest)**:

   **Application Config (`Config`)**:

   ```
   CLI flags > Environment Variables > Defaults
   ```

   **Site Config (`SiteConfig`)**:

   ```
   Environment Variables > Config File (.gomddoc/config.yml) > Defaults
   ```

5. **Extensibility**:
   - `SiteConfig` is designed to support future sections (e.g., `analytics`, `seo`, `navigation`)
   - Keep initial implementation simple - extend when adding new sections
   - Example future extension:
     ```go
     type SiteConfig struct {
         Meta      MetaSection      `env:"META" yaml:"meta"`
         Theme     ThemeSection     `env:"THEME" yaml:"theme"`
         Analytics AnalyticsSection `env:"ANALYTICS" yaml:"analytics"`  // Future
     }
     ```

## Assets Management

### Overlay Filesystem

The assets system uses an **overlay filesystem** pattern with a variadic chain of `fs.FS` interfaces:

1. **Chain of Responsibility**: Multiple `fs.FS` instances are searched in order
2. **First-Found Priority**: Return the first file found in the chain
3. **Fallback**: Continue searching subsequent filesystems if file not found
4. **Error**: Return error only if file not found in ANY filesystem

**Search order example**:

```go
NewOverlayFS(
    os.DirFS(".gomddoc"),  // 1. Check user overrides first (contains assets/)
    embedFS,               // 2. Fall back to embedded assets
)
```

**Lookup behavior**:

```
Request: assets/themes/default/layout.html.tmpl

1. Try: .gomddoc/assets/themes/default/layout.html.tmpl
   → Found? Return it (user override)
   → Not found? Continue to #2

2. Try: embedded:assets/themes/default/layout.html.tmpl
   → Found? Return it (default)
   → Not found? Return error
```

**Benefits**:

- **Flexible**: Can chain any number of `fs.FS` instances
- **Testable**: Easy to mock with `fstest.MapFS`
- **Standard**: Uses Go's `fs.FS` interface
- **Clean**: No special-case logic for directories vs embedded

### Theme Resolution

1. **Theme lookup**: Read `SiteConfig.Theme.Name` from config (e.g., "custom")
2. **Search path**: `assets/themes/{theme_name}/layout.html.tmpl`
3. **Overlay chain**: The `OverlayFS` automatically searches in order:
   - First: `.gomddoc/assets/themes/{theme_name}/layout.html.tmpl`
   - Then: `embedded:assets/themes/{theme_name}/layout.html.tmpl`
4. **Fallback**: If theme doesn't exist, log a **warning** and use "default" theme
5. **Error handling**: If "default" theme is missing in ALL filesystems, this **is an error** (fatal)

### Developer Experience

**Graceful Degradation**:

- Missing custom theme → warn + fallback to "default"
- Missing asset in custom theme → fallback to embedded asset
- Explicit logging for all fallbacks (helps debugging)

## Development Mode & Hot Reload

### Dev Mode Flag

Add `-dev` flag to enable development mode:

```bash
gomddoc -d ./docs -dev         # Enable hot reload. Stick with Golang flags idioms (ie. long args with a single dash)
gomddoc -d ./docs              # Production mode (default)
```

### Hot Reload Behavior

**In Development Mode (`-dev`):**

- Watch `.gomddoc/config.yml` for changes → reload config
- **No template or content caching** - always parse templates fresh
- Log all reloads: `[DEV] Reloaded config.yml`

**In Production Mode (default):**

- Config loaded once at startup
- Template caching enabled (current behavior)
- File watcher **disabled** for performance

### Hot Reload Error Handling

**What happens when reload fails:**

- **Config reload failure** (invalid YAML, parse error):
  - Log error: `[DEV] Failed to reload site config: {error}`
  - **Keep old configuration** (last known good config)
  - Server continues running with previous config
  - Developer is notified via log output
  - No application crash or restart

- **Template reload failure** (parse error, missing file):
  - Log error during template render attempt
  - **Keep cached version** if available
  - Return 500 error for that specific request
  - Other requests continue to work normally

**Design rationale**: Hot reload is a development convenience, not a critical feature. Crashes on reload would disrupt
the development workflow more than preserving stale config.

### Implementation Notes

- Use `fsnotify` library for file watching
- Debounce file events (e.g., 100ms) to avoid multiple rapid reloads
- Only watch `.gomddoc/` directory (not entire content tree)
- Graceful handling if config reload fails (log error, keep old config)

## Security Requirements

### Block Hidden Files and Directories

All hidden files and directories (those starting with `.` in Unix) must **never** be accessible via HTTP, with one
exception:

1. **Middleware**: Add middleware to block any path segment starting with `.` (dot)
2. **Exception**: `.well-known/` is explicitly allowed (IETF RFC 8615 standard)
3. **Response**: Return `404 Not Found` (not 403, to avoid leaking existence)
4. **Logging**: Log blocked attempts at DEBUG level (not INFO - reduces noise, especially under attack)

**Rationale**: Hidden files often contain sensitive data:

- `.gomddoc/` - site configuration and custom assets
- `.git/` - version control history and credentials
- `.env` - environment variables and secrets
- `.htaccess`, `.htpasswd` - server configuration
- `.ssh/` - SSH keys
- `.config/` - application configuration

**`.well-known/` exception**: This directory is an IETF standard (RFC 8615) used for:

- Let's Encrypt ACME challenges (`.well-known/acme-challenge/`)
- Security.txt (`.well-known/security.txt`)
- Change password (`.well-known/change-password`)

**Implementation**: Check **all path segments**, not just the first one.

**Example blocked paths**:

- `GET /.gomddoc/config.yml` → 404 (hidden directory in root)
- `GET /docs/.gomddoc/assets/file.txt` → 404 (hidden directory in subdirectory)
- `GET /.git/config` → 404 (git repository)
- `GET /api/.env` → 404 (environment file)
- `GET /.htaccess` → 404 (hidden file in root)
- `GET /docs/.hidden/file.txt` → 404 (any hidden directory)
- `GET /public/.DS_Store` → 404 (macOS hidden file)

**Example allowed paths**:

- `GET /.well-known/acme-challenge/token` → Allowed (Let's Encrypt)
- `GET /.well-known/security.txt` → Allowed (security contact info)
- `GET /docs/file.txt` → Allowed (normal file)
- `GET /images/logo.png` → Allowed (normal file with extension)

## Template Context Integration

### Updated TemplateContext

**Only `SiteConfig` is exposed to templates, NOT `Config`** (for security):

```go
// internal/template/renderer.go

type TemplateContext struct {
    // Site configuration (public, safe to expose)
    Site *config.SiteConfig

    // Page-specific data (namespaced for extensibility)
    Page PageContext
}

type PageContext struct {
    Content     template.HTML
    Breadcrumbs map[string]string
}
```

**What templates can access**:

- ✅ `SiteConfig` - title, domain, description, theme name
- ✅ `PageContext` - content, breadcrumbs (extensible namespace)
- ❌ `Config` - port, directory, shutdown timeout (security risk)

**Namespacing benefits**:

- **Collision-free**: Site and Page data are clearly separated
- **Extensible**: Can add more page-specific fields without affecting site config
  - Future: `.Page.Author`, `.Page.Date`, `.Page.Tags`, `.Page.Meta`
- **Readable**: Clear intent in templates (`.Site.*` vs `.Page.*`)

### Template Usage

Templates access site configuration via `.Site` and page data via `.Page`:

```html
<!-- Site configuration -->
<title>{{ .Site.Meta.Title }}</title>
<meta name="description" content="{{ .Site.Meta.Description }}" />
<link
  rel="canonical"
  href="https://{{ .Site.Meta.Domain }}{{ .Request.Path }}"
/>

<!-- Theme-specific customization -->
{{ if eq .Site.Theme.Name "dark" }}
<link rel="stylesheet" href="/assets/themes/dark/style.css" />
{{ end }}

<!-- Page content -->
<article>{{ .Page.Content }}</article>

<!-- Breadcrumb navigation -->
{{ range $path, $name := .Page.Breadcrumbs }}
<a href="{{ $path }}">{{ $name }}</a>
{{ end }}
```

**Naming clarification**:

- `.Site` → `*config.SiteConfig` (site-wide configuration)
- `.Site.Meta` → `config.MetaSection` (site metadata section)
- `.Site.Theme` → `config.ThemeSection` (theme configuration section)
- `.Page` → `PageContext` (current page data)
- `.Page.Content` → `template.HTML` (rendered markdown)
- `.Page.Breadcrumbs` → `map[string]string` (navigation breadcrumbs)

### Migration from Current Template

The existing `layout.html.tmpl` will need these changes:

| Current (old)        | New (namespaced)               |
| -------------------- | ------------------------------ |
| `{{ .Title }}`       | `{{ .Site.Meta.Title }}`       |
| `{{ .Description }}` | `{{ .Site.Meta.Description }}` |
| `{{ .Content }}`     | `{{ .Page.Content }}`          |
| `{{ .Breadcrumbs }}` | `{{ .Page.Breadcrumbs }}`      |

**Before**:

```html
<title>{{ .Title }}</title>
<meta name="description" content="{{ .Description }}" />
<article>{{ .Content }}</article>
{{- range $path, $name := .Breadcrumbs }}
```

**After**:

```html
<title>{{ .Site.Meta.Title }}</title>
<meta name="description" content="{{ .Site.Meta.Description }}" />
<article>{{ .Page.Content }}</article>
{{- range $path, $name := .Page.Breadcrumbs }}
```

## Implementation Plan

### Phase 1: Config Package Enhancement

**Files**: `internal/config/config.go` and `internal/config/siteconfig.go`

1. **Add dependencies** (`config.go`):

   ```go
   import (
       "flag"
       "time"
   )
   ```

2. **Define Application Config** (`config.go`):

   ```go
   package config

   // Config holds the application (operational) configuration
   // This is NOT exposed to templates and NOT configurable via .gomddoc/config.yml
   // Configurable via: environment variables + CLI flags (CLI flags take precedence)
   type Config struct {
       // Operational fields (environment variables + CLI flags)
       DefaultIndex    string        `env:"DEFAULT_INDEX"`
       Dir             string        `env:"DIR"`
       Port            string        `env:"PORT"`
       ShutdownTimeout time.Duration `env:"SHUTDOWN_TIMEOUT"`
       DevMode         bool          `env:"DEV_MODE"`

       // Reference to site configuration (this IS exposed to templates)
       Site *SiteConfig
   }

   // New creates a new Config with default values
   func New() *Config {
       defaultDir := "."
       return &Config{
           DefaultIndex:    "README.md",
           Dir:             defaultDir,
           Port:            ":8080",
           ShutdownTimeout: 1 * time.Second,
           DevMode:         false,
           Site:            NewSiteConfig(defaultDir), // Initialize with default dir for title
       }
   }

   // ApplyEnvOverrides applies environment variable overrides to Config using reflection
   // This is called before ParseFlags, so CLI flags take precedence over env vars
   func (c *Config) ApplyEnvOverrides() {
       applyEnvOverridesWithPrefix(c, "GOMDDOC")
   }

   // ParseFlags parses command line flags and updates the configuration
   // Call this AFTER ApplyEnvOverrides so CLI flags take precedence
   func (c *Config) ParseFlags() {
       flag.StringVar(&c.Dir, "d", c.Dir, "Markdown directory")
       flag.StringVar(&c.Port, "p", c.Port, "HTTP port (default: 8080)")
       flag.BoolVar(&c.DevMode, "dev", c.DevMode, "Enable development mode (hot reload)")
       flag.Parse()
   }

   // Validate validates the configuration values
   func (c *Config) Validate() error {
       // Validate application config
       // Site config validation happens separately in SiteConfig.Validate()
       return nil
   }
   ```

3. **Define Site Config** (`siteconfig.go`):

   ```go
   package config

   import (
       "fmt"
       "log/slog"
       "os"
       "path/filepath"
       "reflect"
       "strconv"
       "time"
       "unicode"

       "gopkg.in/yaml.v3"
   )

   // SiteConfig holds the site (content/presentation) configuration
   // This IS exposed to templates and IS configurable via .gomddoc/config.yml
   type SiteConfig struct {
       Meta  MetaSection  `env:"META" yaml:"meta"`
       Theme ThemeSection `env:"THEME" yaml:"theme"`
   }

   type MetaSection struct {
       Domain      string `env:"DOMAIN" yaml:"domain"`
       Title       string `env:"TITLE" yaml:"title"`
       Description string `env:"DESCRIPTION" yaml:"description"`
   }

   type ThemeSection struct {
       Name string `env:"NAME" yaml:"name"`
   }

   // NewSiteConfig creates a new SiteConfig with default values
   // The title defaults to the capitalized basename of the directory
   func NewSiteConfig(dir string) *SiteConfig {
       // Compute default title from directory basename
       absDir, err := filepath.Abs(dir)
       if err != nil {
           absDir = dir // Fallback to original if abs fails
       }
       basename := filepath.Base(absDir)

       // Capitalize first letter
       title := basename
       if len(basename) > 0 {
           runes := []rune(basename)
           runes[0] = unicode.ToUpper(runes[0])
           title = string(runes)
       }

       return &SiteConfig{
           Meta: MetaSection{
               Domain:      "",
               Title:       title,
               Description: "",
           },
           Theme: ThemeSection{
               Name: "default",
           },
       }
   }
   ```

   **Struct tag conventions**:
   - `env:"FIELD_NAME"` - defines the environment variable segment for this field
   - `yaml:"field_name"` - defines the YAML key for this field
   - Only fields with `env` tag are overridable via environment variables
   - Nested structs use tags to build hierarchical env var names: `PREFIX_PARENT_CHILD`
   - Example: `GOMDDOC_META_TITLE` → `SiteConfig.Meta.Title`

4. **Add YAML loading to SiteConfig** (`siteconfig.go`):

   ```go
   // LoadFromFile loads site config from .gomddoc/config.yml
   func (sc *SiteConfig) LoadFromFile(rootDir string) error {
       path := filepath.Join(rootDir, ".gomddoc", "config.yml")

       // Missing file is NOT an error - use defaults
       if _, err := os.Stat(path); os.IsNotExist(err) {
           slog.Debug("No site config file found, using defaults",
               slog.String("path", path))
           return nil
       }

       data, err := os.ReadFile(path)
       if err != nil {
           return fmt.Errorf("read config file: %w", err)
       }

       // Parse YAML directly into SiteConfig
       // This will use the yaml struct tags
       if err := yaml.Unmarshal(data, sc); err != nil {
           return fmt.Errorf("parse config.yml: %w", err)
       }

       slog.Info("Loaded site configuration",
           slog.String("path", path),
           slog.String("title", sc.Meta.Title),
           slog.String("theme", sc.Theme.Name))

       return nil
   }
   ```

   **Note**: We parse directly into `SiteConfig` because the YAML structure matches:

   ```yaml
   meta: # → SiteConfig.Meta (MetaSection)
     title: "..."
   theme: # → SiteConfig.Theme (ThemeSection)
     name: "..."
   ```

5. **Add shared reflection-based environment variable overrides** (`siteconfig.go`):

   ```go
   // ApplyEnvOverrides applies environment variable overrides using reflection
   // Environment variable names are built from:
   // - Configurable prefix (default: "GOMDDOC")
   // - Struct field env tags in hierarchical order
   // Example: GOMDDOC_META_TITLE, GOMDDOC_THEME_NAME
   func (sc *SiteConfig) ApplyEnvOverrides() {
       applyEnvOverridesWithPrefix(sc, "GOMDDOC")
   }

   // applyEnvOverridesWithPrefix applies env overrides to any struct with env tags
   // This is a shared helper used by both Config and SiteConfig
   func applyEnvOverridesWithPrefix(target any, prefix string) {
       v := reflect.ValueOf(target).Elem()
       t := v.Type()
       walkStruct(v, t, prefix)
   }

   // walkStruct recursively walks any struct and applies env overrides
   // This is a shared helper used by both Config and SiteConfig
   func walkStruct(v reflect.Value, t reflect.Type, prefix string) {
       for i := 0; i < v.NumField(); i++ {
           field := v.Field(i)
           fieldType := t.Field(i)

           // Skip unexported fields
           if !field.CanSet() {
               continue
           }

           // Get env tag (skip if not present)
           envTag := fieldType.Tag.Get("env")
           if envTag == "" {
               continue
           }

           // Build full env var name
           envVarName := prefix + "_" + envTag

           // Handle based on field kind
           switch field.Kind() {
           case reflect.Struct:
               // Recurse into nested struct (builds hierarchical env var names)
               walkStruct(field, field.Type(), envVarName)

           case reflect.Ptr:
               // Skip pointer fields (e.g., Config.Site which is *SiteConfig)
               // These are configured separately
               continue

           case reflect.String:
               // Leaf node: check env var and set if present
               if envValue := os.Getenv(envVarName); envValue != "" {
                   field.SetString(envValue)
                   slog.Debug("Applied env override",
                       slog.String("var", envVarName),
                       slog.String("value", envValue))
               }

           case reflect.Int, reflect.Int64:
               // Support for int and duration types
               if envValue := os.Getenv(envVarName); envValue != "" {
                   // Check if it's a time.Duration field
                   if field.Type() == reflect.TypeOf(time.Duration(0)) {
                       if duration, err := time.ParseDuration(envValue); err == nil {
                           field.SetInt(int64(duration))
                           slog.Debug("Applied env override (duration)",
                               slog.String("var", envVarName),
                               slog.String("value", envValue))
                       } else {
                           slog.Warn("Invalid duration format",
                               slog.String("var", envVarName),
                               slog.String("value", envValue))
                       }
                   } else {
                       // Regular int
                       if intValue, err := strconv.ParseInt(envValue, 10, 64); err == nil {
                           field.SetInt(intValue)
                           slog.Debug("Applied env override (int)",
                               slog.String("var", envVarName),
                               slog.String("value", envValue))
                       } else {
                           slog.Warn("Invalid int format",
                               slog.String("var", envVarName),
                               slog.String("value", envValue))
                       }
                   }
               }

           case reflect.Bool:
               // Support for bool types
               if envValue := os.Getenv(envVarName); envValue != "" {
                   if boolValue, err := strconv.ParseBool(envValue); err == nil {
                       field.SetBool(boolValue)
                       slog.Debug("Applied env override (bool)",
                           slog.String("var", envVarName),
                           slog.String("value", envValue))
                   } else {
                       slog.Warn("Invalid bool format",
                           slog.String("var", envVarName),
                           slog.String("value", envValue))
                   }
               }
           }
       }
   }
   ```

   func (sc *SiteConfig) Validate() error {
       // Validate theme name is not empty
       if sc.Theme.Name == "" {
           sc.Theme.Name = "default"  // Auto-fix
           slog.Warn("Empty theme name, using default")

           if strings.Contains(sc.Meta.Domain, "/") {

           }

   }

   **Design rationale**:
   - **Reflection-based**: Automatically handles new config fields without code changes (shared between Config and SiteConfig)
   - **Struct tags**: Single source of truth for env var names
   - **Type-safe**: Supports string, int, bool, time.Duration with proper parsing
   - **Hierarchical**: Builds env var names from nested struct tags (e.g., `GOMDDOC_META_TITLE`)
   - **Flat for Config**: Top-level fields use flat naming (e.g., `GOMDDOC_PORT` not `GOMDDOC_CONFIG_PORT`)
   - **Explicit opt-in**: Only fields with `env` tag are processed
   - **Configurable prefix**: Allows different prefixes for testing or multi-tenant setups
   - **Logging**: Debug logs for applied overrides, warnings for parse errors
   - **Graceful**: Parse errors are logged but don't crash the application
   - **Shared implementation**: Same reflection code works for both Config and SiteConfig

   **Reflection limitations**:
   - **Supported types**: `string`, `int`, `int64`, `bool`, `time.Duration`, nested structs
   - **Skipped types**: pointers (e.g., `*SiteConfig` in Config is skipped - configured separately)
   - **NOT supported**: slices (`[]string`), maps (`map[string]string`), interfaces
   - **Struct handling**: Only exported fields with `env` tag are processed
   - **Error handling**: Invalid type conversions log warnings but don't fail
   - **Performance**: Reflection overhead is negligible at startup (runs once for each config)
   - **Future extensibility**: Can add support for slices/maps if needed in future versions

1. **Create variadic overlay FS implementation**:

   ```go
   package assets

   import (
       "errors"
       "io/fs"
       "log/slog"
   )

   // OverlayFS implements fs.FS by searching through a chain of filesystems
   // Files are returned from the first filesystem that contains them
   type OverlayFS struct {
       filesystems []fs.FS  // Searched in order
   }

   // NewOverlayFS creates a new overlay filesystem from a variadic list of fs.FS
   // Filesystems are searched in the order provided (first has highest priority)
   // Example: NewOverlayFS(userOverrides, embeddedAssets)
   func NewOverlayFS(filesystems ...fs.FS) *OverlayFS {
       return &OverlayFS{
           filesystems: filesystems,
       }
   }

   // Open implements fs.FS interface
   // Searches through filesystems in order, returning the first match
   func (o *OverlayFS) Open(name string) (fs.File, error) {
       var lastErr error

       for i, filesystem := range o.filesystems {
           f, err := filesystem.Open(name)
           if err == nil {
               // File found in this filesystem
               slog.Debug("File found in overlay filesystem",
                   slog.String("file", name),
                   slog.Int("fs_index", i))
               return f, nil
           }

           // Save error for potential debugging
           lastErr = err

           // Continue searching if file not found
           if errors.Is(err, fs.ErrNotExist) {
               continue
           }

           // For other errors (permission, etc), also continue
           // but log a warning
           slog.Debug("Error accessing file in filesystem",
               slog.String("file", name),
               slog.Int("fs_index", i),
               slog.Any("error", err))
       }

       // File not found in any filesystem
       if lastErr != nil {
           return nil, lastErr
       }
       return nil, fs.ErrNotExist
   }

   // ReadFile provides optimized ReadFile implementation
   func (o *OverlayFS) ReadFile(name string) ([]byte, error) {
       var lastErr error

       for _, filesystem := range o.filesystems {
           data, err := fs.ReadFile(filesystem, name)
           if err == nil {
               return data, nil
           }

           lastErr = err

           if errors.Is(err, fs.ErrNotExist) {
               continue
           }
       }

       if lastErr != nil {
           return nil, lastErr
       }
       return nil, fs.ErrNotExist
   }
   ```

   ```go
   package template

   import (
       "html/template"
       "sync"
   )

   // TemplateCache is an interface for caching parsed templates
   // Implementations: CachedTemplateStore (production), PassthroughTemplateStore (dev mode)
   type TemplateCache interface {
       // Get retrieves a template from cache, returns nil if not found
       Get(key string) *template.Template

       // Set stores a template in cache
       Set(key string, tmpl *template.Template)

       // Clear removes all cached templates (used in dev mode hot reload)
       Clear()
   }

   // CachedTemplateStore caches templates for production use
   // Thread-safe implementation using sync.Map
   type CachedTemplateStore struct {
       cache sync.Map
   }

   func (c *CachedTemplateStore) Get(key string) *template.Template {
       if val, ok := c.cache.Load(key); ok {
           return val.(*template.Template)
       }
       return nil
   }

   func (c *CachedTemplateStore) Set(key string, tmpl *template.Template) {
       c.cache.Store(key, tmpl)
   }

   func (c *CachedTemplateStore) Clear() {
       c.cache.Range(func(key, value any) bool {
           c.cache.Delete(key)
           return true
       })
   }

   // PassthroughTemplateStore is a no-op cache for development mode
   // Always returns nil on Get, forcing template re-parsing on every request
   type PassthroughTemplateStore struct{}

   func (p *PassthroughTemplateStore) Get(key string) *template.Template {
       return nil // Always miss - forces re-parsing
   }

   func (p *PassthroughTemplateStore) Set(key string, tmpl *template.Template) {
       // No-op - don't cache in dev mode
   }

   func (p *PassthroughTemplateStore) Clear() {
       // No-op - nothing to clear
   }

   // NewTemplateCache creates appropriate cache implementation based on dev mode
   // Factory pattern: devMode=true → PassthroughTemplateStore, devMode=false → CachedTemplateStore
   func NewTemplateCache(devMode bool) TemplateCache {
       if devMode {
           return &PassthroughTemplateStore{}
       }
       return &CachedTemplateStore{}
   }
   ```

   **Design rationale**:
   - **Strategy Pattern**: Cache behavior selected at initialization, not runtime
   - **Separation of Concerns**: Caching logic isolated from rendering logic
   - **Single Responsibility**: Each implementation has one job
   - **Open/Closed**: Easy to add new cache strategies (LRU, TTL, size-limited) without modifying renderer
   - **Dependency Inversion**: Renderer depends on abstraction (interface), not concrete implementations
   - **No Config Leakage**: DevMode flag stays in main.go, doesn't leak into rendering layer
   - **Performance**: No conditional branches in hot path (Render method)
   - **Testability**: Easy to mock cache, inject test doubles

1. **Add hidden files/directories blocking middleware**:

   ```go
   package server

   import (
       "log/slog"
       "net/http"
       "strings"
   )

   // BlockHiddenPaths blocks HTTP access to hidden files and directories
   // Hidden files/directories are those starting with a dot (.) in Unix
   // This protects .gomddoc/, .git/, .env, .htaccess, .ssh/, etc.
   // Exception: .well-known/ is allowed (IETF RFC 8615 standard)
   func BlockHiddenPaths(next http.Handler) http.Handler {
       return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
           // Split path into segments
           path := strings.TrimPrefix(r.URL.Path, "/")
           segments := strings.Split(path, "/")

           // Check each segment for hidden files/directories
           for _, segment := range segments {
               if segment == "" {
                   continue
               }

               // Allow .well-known (IETF RFC 8615 - used for Let's Encrypt, security.txt, etc.)
               if segment == ".well-known" {
                   continue
               }

               // Block if segment starts with a dot
               if strings.HasPrefix(segment, ".") {
                   slog.Debug("Blocked hidden path access",
                       slog.String("path", r.URL.Path),
                       slog.String("segment", segment),
                       slog.String("remote", r.RemoteAddr))

                   w.Header().Set("Content-Type", "text/plain; charset=utf-8")
                   w.WriteHeader(http.StatusNotFound)
                   w.Write([]byte("File not found"))
                   return
               }
           }

           next.ServeHTTP(w, r)
       })
   }
   ```

### Phase 5: Development Mode Hot Reload

**New File**: `internal/watcher/watcher.go`

1. **Create file watcher**:

   ```go
   package watcher

   import (
       "log/slog"
       "path/filepath"
       "time"

       "github.com/fsnotify/fsnotify"
   )

   // Watcher watches .gomddoc directory for changes
   type Watcher struct {
       watcher       *fsnotify.Watcher
       gomddocPath   string
       debounceTimer *time.Timer
       onConfigChange func()
       onAssetChange  func()
   }

   // New creates a new file watcher
   func New(rootDir string, onConfigChange, onAssetChange func()) (*Watcher, error) {
       fsWatcher, err := fsnotify.NewWatcher()
       if err != nil {
           return nil, err
       }

       gomddocPath := filepath.Join(rootDir, ".gomddoc")

       w := &Watcher{
           watcher:        fsWatcher,
           gomddocPath:    gomddocPath,
           onConfigChange: onConfigChange,
           onAssetChange:  onAssetChange,
       }

       // Watch .gomddoc directory
       if err := fsWatcher.Add(gomddocPath); err != nil {
           // Not an error if .gomddoc doesn't exist
           slog.Debug(".gomddoc directory not found, skipping watch",
               slog.String("path", gomddocPath))
       } else {
           // Also watch assets subdirectory
           assetsPath := filepath.Join(gomddocPath, "assets")
           if err := fsWatcher.Add(assetsPath); err == nil {
               slog.Debug("Watching assets directory", slog.String("path", assetsPath))
           }
       }

       return w, nil
   }

   // Start starts watching for file changes
   func (w *Watcher) Start() {
       go func() {
           for {
               select {
               case event, ok := <-w.watcher.Events:
                   if !ok {
                       return
                   }

                   w.handleEvent(event)

               case err, ok := <-w.watcher.Errors:
                   if !ok {
                       return
                   }
                   slog.Error("Watcher error", slog.Any("error", err))
               }
           }
       }()
   }

   // handleEvent processes file system events with debouncing
   func (w *Watcher) handleEvent(event fsnotify.Event) {
       // Debounce: wait 100ms before triggering reload
       if w.debounceTimer != nil {
           w.debounceTimer.Stop()
       }

       w.debounceTimer = time.AfterFunc(100*time.Millisecond, func() {
           filename := filepath.Base(event.Name)

           if filename == "config.yml" && (event.Op&fsnotify.Write == fsnotify.Write) {
               slog.Info("[DEV] Config file changed, reloading...",
                   slog.String("file", event.Name))
               w.onConfigChange()
           } else if event.Op&fsnotify.Write == fsnotify.Write {
               slog.Info("[DEV] Asset changed, clearing cache...",
                   slog.String("file", event.Name))
               w.onAssetChange()
           }
       })
   }

   // Close stops the watcher
   func (w *Watcher) Close() error {
       if w.debounceTimer != nil {
           w.debounceTimer.Stop()
       }
       return w.watcher.Close()
   }
   ```

2. **Update main.go to use watcher** (updated for new cache architecture):

       provider, err := provider.NewFilesystemProvider(cfg.Dir, cfg.DefaultIndex)

                   renderer.ClearCache()
               },

               slog.Warn("Could not start file watcher", slog.Any("error", err))

           }

   }

- ✅ **Dynamic default title**: Automatically derived from capitalized basename of the directory specified by `-d` flag
- ✅ **Reflection-based environment variable overrides** for both Config and SiteConfig
- ✅ Environment variable naming from struct tags:
  - Application config: `GOMDDOC_PORT`, `GOMDDOC_DIR`, `GOMDDOC_DEV_MODE`
  - Site config: `GOMDDOC_META_TITLE`, `GOMDDOC_THEME_NAME`
- ✅ **Dual precedence models**:
  - Application config: CLI flags > Env vars > Defaults
  - Site config: Env vars > YAML > Defaults (with dynamic title default)
- ✅ Type-safe config with support for string, int, bool, and time.Duration
- ✅ **Template cache interface**: Strategy pattern with `CachedTemplateStore` (production) and `PassthroughTemplateStore` (dev mode)
  - Zero config leakage to rendering layer
  - No runtime conditionals in render path
  - Dependency injection for testability
- ✅ Variadic overlay filesystem with chain-of-responsibility pattern
- ✅ Theme system with graceful fallback
- ✅ Development mode with hot reload (`-dev` flag)
- ✅ Security (block all hidden files/directories starting with `.` from HTTP, except `.well-known/`)
- ✅ Template context integration with namespaced Page data
- ✅ Backward compatibility
- ✅ Extensible design for future features

The implementation is broken into 6 phases with clear deliverables, tests, and integration points.

### Key Architectural Decisions

1. **Config/SiteConfig separation**: Configuration is split into two distinct structs:
   - **`Config`** (application/operational): Runtime settings like port, directory, dev mode. **NOT exposed to templates** for security. Only configurable via CLI flags.
   - **`SiteConfig`** (site/presentation): User-facing settings like title, theme, domain. **Exposed to templates** safely. Configurable via `.gomddoc/config.yml` + environment variables.

   **Security benefit**: Templates cannot access server internals (port numbers, file paths, shutdown timeouts).

2. **Reflection-based environment overrides**: Using Go reflection to automatically map struct tags to environment variables eliminates manual override code and ensures consistency as the config schema grows. **Shared implementation** works for both `Config` and `SiteConfig` using the same `walkStruct()` helper function.

3. **Struct tag convention**: The `env:"FIELD_NAME"` tag pattern creates a single source of truth for environment variable naming, making the system self-documenting and maintainable. Examples:
   - Application config (flat): `GOMDDOC_PORT` → `Config.Port`
   - Site config (nested): `GOMDDOC_META_TITLE` → `SiteConfig.Meta.Title`

4. **Template cache interface (Strategy Pattern)**: Template caching is implemented as an interface with two concrete implementations:
   - **`CachedTemplateStore`** (production): Thread-safe caching using `sync.Map` for optimal performance
   - **`PassthroughTemplateStore`** (dev mode): No-op implementation that always forces re-parsing

   **Benefits of this design**:
   - **Zero config leakage**: `DevMode` flag stays in `main.go`, never reaches the rendering layer
   - **Separation of concerns**: Caching logic is isolated from rendering logic (Single Responsibility Principle)
   - **No runtime conditionals**: Cache behavior selected at initialization via factory pattern, not checked on every render
   - **Dependency inversion**: Renderer depends on `TemplateCache` interface, not concrete implementations
   - **Open/Closed Principle**: Easy to add new cache strategies (LRU, TTL-based, size-limited) without modifying renderer
   - **Elegant dev mode**: PassthroughTemplateStore makes `Get()` always return `nil` and `Set()`/`Clear()` no-ops
   - **Testability**: Trivial to inject mock cache for testing, verify caching behavior in isolation
   - **Performance**: Single code path in `Render()` method eliminates conditional branches in hot path

   **Factory pattern**: `NewTemplateCache(devMode bool)` creates the appropriate implementation, encapsulating the decision logic.

   **SOLID principles demonstrated**:
   - **Single Responsibility**: `CachedTemplateStore` does caching, `PassthroughTemplateStore` does pass-through, `HTMLRenderer` does rendering
   - **Open/Closed**: Can add new cache implementations (LRU, Redis-backed, etc.) without modifying renderer
   - **Liskov Substitution**: Both cache implementations are fully interchangeable via the `TemplateCache` interface
   - **Interface Segregation**: `TemplateCache` has minimal interface (Get/Set/Clear) - clients only depend on what they need
   - **Dependency Inversion**: High-level `HTMLRenderer` depends on `TemplateCache` abstraction, not low-level cache implementations

   **Alternative approaches considered and rejected**:
   - ❌ **Conditional in Render()**: Would leak config into renderer, create branching in hot path, reduce testability
   - ❌ **Two separate Renderer implementations**: Would duplicate rendering logic, violate DRY principle
   - ❌ **Config flag checking**: Would couple renderer to config struct, make testing harder
   - ✅ **Strategy Pattern** (chosen): Clean separation, zero config leakage, optimal performance, maximum testability

5. **Dual precedence models**: Different precedence rules for different config types:
   - **Application config**: CLI flags > Env vars > Defaults (allows deployment-time overrides)
   - **Site config**: Env vars > YAML > Defaults (allows environment-specific customization)

6. **Dynamic default title**: The site title defaults to the capitalized basename of the directory specified by the `-d` flag. This provides meaningful defaults without hardcoding a generic name. The title is computed from the resolved absolute path, ensuring consistency. If users want a different title, they can override it via `config.yml` or environment variables.

7. **Graceful degradation**: Missing config files, invalid values, and missing themes all degrade gracefully with appropriate logging rather than causing failures.

8. **Dev mode separation**: The `-dev` flag clearly separates development (hot reload, no caching) from production (cached, performant) workflows. Hot reload only applies to `SiteConfig` and templates, not application config.

9. **Variadic overlay filesystem**: Asset system uses a chain-of-responsibility pattern with variadic `fs.FS` arguments. Files are loaded from the first filesystem that contains them, enabling flexible asset overlays without special-case logic.
