# Internationalization and Localization

**Date**: 2026-04-10
**Status**: Approved

## Goal

Add i18n/l10n support to gomddoc: translated UI strings for theme chrome, and
multi-language content trees served under BCP 47 URL prefixes (e.g., `fr-FR`).
Single-language sites are unaffected — i18n is fully opt-in.

## Language Detection

**Serve mode**: language is detected from the URL path prefix. A request to
`/fr-FR/guide` uses locale `fr-FR`. No prefix → `language` config key → `en-US`.

**Build mode**: language is detected from the file path prefix. `fr-FR/guide.md`
uses locale `fr-FR`. No prefix → `language` config key → `en-US`.

**BCP 47 pattern**: language tags like `en-US`, `fr-FR`, `pt-BR`. Directories
matching this pattern in the content root are treated as language subtrees.

## Configuration

```yaml
language: en-US  # optional, default en-US
```

No `languages` map. Languages are auto-discovered from BCP 47 directories in
the content root. The default language content lives at the root (no prefix
folder, no URL prefix).

## Locale System

New package `internal/locale/`.

### Bundle

```go
type Bundle struct {
    defaultLang string
    strings     map[string]map[string]string  // lang → key → value
}

func (b *Bundle) T(lang, key string) string
```

`T` returns the translated string for the given language and key. Fallback chain:
requested language → default language → key itself (guarantees no empty output).

### Locale File Format

Flat YAML with BCP 47 filenames:

```yaml
# locales/en-US.yml
language_name: English
toc_title: "On this page"
edit_page: "Edit this page"
go_to_homepage: "Go to homepage"
search_placeholder: "Search documentation..."
search_no_results: "No results found"
search_navigate: Navigate
search_open: Open
search_close: Close
copy: Copy
copied: "Copied!"
aria_toggle_nav: "Toggle navigation"
aria_site_nav: "Site navigation"
aria_search: "Search documentation"
aria_toc: "Table of contents"
aria_toggle_toc: "Toggle table of contents"
aria_toggle_theme: "Toggle dark mode"
aria_breadcrumb: Breadcrumb
aria_copy_code: "Copy code to clipboard"
search_shortcut: "Search (Ctrl+K)"
```

The `language_name` key provides the display name for the language switcher
(e.g., "Français"). Falls back to the BCP 47 code if missing.

### Loading Order (highest wins)

1. Site-level: `.gomddoc/locales/{lang}.yml` (user overrides)
2. Theme-level: `assets/themes/{theme}/locales/{lang}.yml` (theme customizations)
3. Built-in: embedded `locales/en-US.yml` (baseline)

### Shipped Locales

Only `en-US.yml` ships with the binary. Other languages are added by site authors
in `.gomddoc/locales/`.

## Multi-Instance Pipeline

Each discovered language gets its own pipeline instance:

- **Provider** — scoped to `{root}/{lang}/` (or root for default)
- **Metadata index**
- **Search index**
- **Navigation tree**

### Content Structure

```
content root/
├── guide.md              ← default language (en-US)
├── fr-FR/
│   └── guide.md          ← French → /fr-FR/guide
└── es-ES/
    └── guide.md          ← Spanish → /es-ES/guide
```

### Request Routing

Middleware extracts the BCP 47 prefix from the URL path and dispatches to the
correct pipeline. The prefix is stripped before the handler sees it — each
pipeline works identically to a standalone single-language site.

### Per-Language Endpoints

- **Sitemap**: `/sitemap.xml` (default), `/fr-FR/sitemap.xml` (French)
- **Feed**: `/feed.xml` (default), `/fr-FR/feed.xml` (French)
- **Sitemap index**: `/sitemap-index.xml` (only when multiple languages exist)

### API Language Selection

API endpoints (e.g., `/api/search`) remain at a single path. The requested
language is determined by (highest priority wins):

1. `lang` query string parameter: `/api/search?q=guide&lang=fr-FR`
2. `Accept-Language` HTTP header: `Accept-Language: fr-FR`
3. Default language from config (falls back to `en-US`)

The API dispatches to the pipeline matching the resolved language. Unknown
language values fall back to the default.

### MCP

Serves default language content only. Multi-language MCP is out of scope.

## Template Integration

### `T` Function

New template function resolving the current page's language from request context:

```html
<h3>{{ T "toc_title" }}</h3>
<a href="/">{{ T "go_to_homepage" }}</a>
```

### `<html lang>` Attribute

Set directly from the current BCP 47 language tag:

```html
<html lang="fr-FR">
```

### JavaScript Strings

Templates pass translated strings to JS via `data-` attributes:

```html
<div id="search-modal"
     data-placeholder="{{ T "search_placeholder" }}"
     data-no-results="{{ T "search_no_results" }}">
```

`search.mjs` and `code-copy.mjs` read from these attributes instead of
hardcoded strings.

### Language Switcher

New partial `lang-switcher.html.tmpl` rendered in the header. Lists all
discovered languages with links to `/{lang}/{current_path}`. No cross-pipeline
existence check — missing translations return 404.

Display names come from `language_name` in locale files, falling back to the
BCP 47 code.

Available languages are passed to the template context via a `Languages` field
(list of `{Code, Name, Active}` structs).

### `hreflang` Tags

Added to the `head` partial:

```html
<link rel="alternate" hreflang="fr-FR" href="/fr-FR/guide">
<link rel="alternate" hreflang="x-default" href="/guide">
```

One tag per discovered language, plus `x-default` pointing to the default
language version.

## Theme Updates

All 8 themes (default + 7 in gomddoc-themes) receive:

1. Hardcoded strings replaced with `{{ T "key" }}` (~20 keys)
2. `lang-switcher.html.tmpl` partial added, styled per theme
3. `hreflang` links added to `head` partial
4. `<html lang>` set from BCP 47 language tag

Default theme ships first. gomddoc-themes updated in a follow-up.

Themes can ship locale overrides (e.g., midnight's "Edit this page on GitHub")
via `locales/en-US.yml` in their theme directory.

## Build Mode

**Output structure**:

```
build/
├── index.html
├── guide/index.html
├── sitemap.xml
├── feed.xml
├── fr-FR/
│   ├── index.html
│   ├── guide/index.html
│   ├── sitemap.xml
│   └── feed.xml
├── sitemap-index.xml      # only if multiple languages
└── robots.txt             # references sitemap-index.xml or sitemap.xml
```

Each language built with its own pipeline instance. Error pages generated per
language (`404.html`, `fr-FR/404.html`).

## Testing

**Unit tests:**
- `internal/locale/`: bundle loading, fallback chain, locale file merging
  across layers
- BCP 47 directory detection: pattern matching, edge cases
- Language extraction from URL path and file path

**Integration tests:**
- Multi-language server: correct UI strings, `<html lang>`, `hreflang` tags
- Single-language site: no regressions, behaves as today
- Per-language sitemap, sitemap index
- Per-language search API
- Build output directory structure

**Out of scope:**
- Theme-specific language switcher styling (visual, manual)
- Translation accuracy
