# Architecture Specification - Phase 1 Restructuring

> **Status: Completed.** This spec documents the Phase 1 restructuring from a single `main.go` to a multi-package
> architecture. The project has since evolved through Phase 2 (content rendering system) and Phase 3 (Git provider,
> configuration, security hardening). See [architecture.md](../architecture.md) for current architecture and
> [roadmap.md](../roadmap.md) for future plans. Coverage has grown from 54.9% → 78.1%.

## Overview

This document outlines the first phase of restructuring gomddoc from a single-file implementation into a proper Go
project architecture while maintaining 100% backward compatibility and current functionality.

## Current Implementation Analysis

### Existing Structure (Single File)
- **File**: `main.go` (~192 lines)
- **Test Coverage**: 54.9% (target: maintain or improve to 55%+)
- **Core Components**:
  - Configuration management (`Config` struct, `newConfig()`)
  - Markdown processing (`mdToHTML()`)
  - HTTP handler (`newServeHTTP()`)
  - Security middleware (`securityHeaders()`)
  - Template rendering (inline HTML template)
  - Graceful shutdown (errgroup pattern)

### Current Functionality
- [x] Serves Markdown files as HTML
- [x] Path traversal protection via `os.OpenRoot()`
- [x] Security headers (X-Content-Type-Options, X-Frame-Options)
- [x] Cache headers (5-minute public cache)
- [x] Proper HTTP status codes (404, 500)
- [x] Graceful shutdown with signal handling
- [x] Configurable directory and port via flags
- [x] Template-based HTML rendering
- [x] Default index file support (README.md)

## Implementation Plan

### Phase 1A: Core Infrastructure
1. **Configuration Package** (`internal/config/`)
   - Extract `Config` struct and `newConfig()` function
   - Add validation and default value methods
   - Maintain same CLI flag interface

2. **Provider Package** (`internal/provider/`)
   - Create `Provider` interface
   - Implement `FilesystemProvider` with `os.OpenRoot()` security
   - Maintain exact same file access behavior

3. **Processor Package** (`internal/processor/`)
   - Create `Processor` interface
   - Implement `MarkdownProcessor` with goldmark configuration
   - Maintain exact same HTML output

### Phase 1B: Server Infrastructure
4. **Template Package** (`internal/template/`)
   - Create `Renderer` interface
   - Implement `HTMLRenderer` with embedded assets support
   - Maintain same template context structure

5. **Server Package** (`internal/server/`)
   - Extract HTTP handler logic into `handler.go`
   - Extract middleware into `middleware.go`
   - Create `Server` interface with lifecycle management
   - Maintain exact same HTTP behavior

6. **CLI Package** (`cmd/gomddoc/`)
   - Extract main function to CLI entry point
   - Maintain same graceful shutdown with errgroup
   - Wire up all components with dependency injection

### Phase 1C: Testing & Validation
7. **Test Migration**
   - Split existing tests across appropriate packages
   - Maintain or improve 54.9% → 55%+ coverage
   - Add integration tests for wired components
   - Ensure all existing test scenarios pass

8. **Validation**
   - Verify identical HTTP responses
   - Verify identical error handling
   - Verify identical performance characteristics
   - Verify identical configuration behavior
