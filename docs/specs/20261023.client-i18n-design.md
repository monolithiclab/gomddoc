# Design: Localized Strings for Client-Side Modules

**Date:** 2026-10-23
**Status:** Draft, awaiting validation. Settled 2026-10-23: JSON data blocks rather than `<html>` attributes or a
global, one block per namespace from the start so extensions use the same mechanism, and the code-copy keys renamed
to `code_copy_*`.

## Intent

The browser modules that build UI at runtime (code-copy buttons, the search dialog, annotations, color chips) need
the page language's strings. Today they get them two different ways:

| Module                        | Source of strings                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------- |
| `code-copy.mjs`, `search.mjs` | Ten `data-*` attributes each layout must write on `<html>` (`default.html.tmpl`, `error.html.tmpl`)       |
| `gmd-annotations.mjs`         | `labels` inside its own `<script type="application/json" id="gmd-annotations-config">`, read by `labeler` |
| `gmd-color-chip.mjs`          | None: `Color ${value}` is hard-coded English                                                              |
| `search.mjs` (two labels)     | None: `aria-label="Search query"` and `"Search results"` are hard-coded English                           |

The attribute approach failed where it matters: all seven downloadable themes load `search.mjs` and `code-copy.mjs`
through `scripts-shared` but none writes the attributes, so on a `fr-FR` page in those themes the search dialog and
copy buttons are always English and the search tip never shows. The marketing site copies the eleven attributes by
hand. The strings depend on a tag every layout must repeat, instead of on the partial that loads the script.

## Goals

- One mechanism for every client-side string: the partial that loads a module also emits that module's strings, so
  any theme calling `scripts-shared` is localized with no theme change.
- Extensions (a custom theme's own scripts) use the same mechanism with their own keys, and nothing merges
  dictionaries: each module reads only its own namespace.
- Plural forms chosen by CLDR rules for the page language, not `n === 1`.
- Placeholders a translator can reorder.
- Every runtime string localized, including the three hard-coded English labels.

## Non-goals

- Rewriting the search modal as a server-rendered `<dialog>` whose text comes from `.T` directly. That is the better
  end state (it removes most client strings and follows the native-`<dialog>` rule), but it is a separate change;
  park it in `ROADMAP.md`.
- `Intl.MessageFormat` / MessageFormat 2 syntax. The proposal is at TC39 Stage 1; revisit when it ships.
- Theme-level locale files. Themes still do not ship translations; an extension's keys live in the site's
  `.gomddoc/locales/`.
- `theme-toggle.mjs`'s `data-light` / `data-dark` attributes. They sit on the element they describe, which is what
  `data-*` is for.
- Strings injected by scripts after load. Blocks are read from the parsed HTML only.

## Anti-goals

- A global variable or object (`window.gomddoc…`). Executable code for data, namespace pollution, script-order
  coupling.
- A merged, flat dictionary across blocks, with precedence rules between them.
- A key appearing as raw key text in a theme that worked before because a block went missing silently: the shared
  partial emits the block inside the same `.Feature` guard as the module, so one is never there without the other.

## Design

### The data blocks

Each module's strings travel in one data block, emitted by the template next to the module:

```html
<script type="application/json" data-gmd-i18n="search">
  {{ i18nStrings . "search" }}
</script>
<script type="module">
  {{ inlineJSAsset "search.mjs" }}
</script>
```

- `data-gmd-i18n` names the **namespace**. The namespace is a key prefix: the block holds every bundle key starting
  with it (plain `strings.HasPrefix`, as `Bundle.Keys` does today, so `annotation` covers `annotation_*` and
  `annotations_*`, and `search` also carries the server-only `search_shortcut`, which is harmless).
- `i18nStrings tc namespace` is a template function returning `map[string]string`: for each key with the prefix, the
  page language's translation (`tc.T(key)`), **omitting keys whose translation is the key itself**, so the client
  falls back exactly like the server. It takes the template context, as `annotationsConfig` does, so the funcMap
  binding trap in `AGENTS.md` does not apply. `html/template` marshals the map in the JSON script context, which
  escapes `<`, `>` and `&` (`</script>` in a translation cannot close the block).
- The renderer gets the bundle's full key list once (replacing `WithAnnotationLabelKeys` / `labelKeys` /
  `PipelineOptions.AnnotationLabelKeys`) and filters by prefix per call.
- `AnnotationsConfig` loses `Labels`; it keeps `sourcePath` and `title`.

Namespaces and the keys they carry:

| Namespace    | Keys                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `code_copy`  | `code_copy_label` ("Copy"), `code_copy_done` ("Copied!"), `code_copy_aria` ("Copy code to clipboard")                                                                    |
| `search`     | the existing `search_*` keys, plus new `search_label` ("Search documentation", the dialog's label), `search_query` ("Search query"), `search_results` ("Search results") |
| `annotation` | the existing `annotation_*` and `annotations_*` keys                                                                                                                     |
| `color_chip` | new `color_chip_label` ("Color %s")                                                                                                                                      |

**Renamed keys** (user-visible: a site overriding them in `.gomddoc/locales/` must rename them):
`copy` → `code_copy_label`, `copied` → `code_copy_done`, `aria_copy_code` → `code_copy_aria`. `aria_search` stays:
the header button (server-rendered) keeps using it; the dialog gets `search_label`.

### The helper module

`assets/shared/static/gmd-i18n.mjs`, served at `/_assets/gmd-i18n.mjs` by `serve` and written to
`_assets/gmd-i18n.mjs` by `build` (it must sit under `shared/static/`, the directory `BuildStaticFS` exposes; the
other shared modules are inlined and never served by URL). Modules import it by that absolute path, the same path
`assetURL` produces; gomddoc has no sub-path hosting, so this adds no new limitation.

```js
import { i18n } from "/_assets/gmd-i18n.mjs";
const { t, tn } = i18n("search");
t("search_placeholder"); // "Rechercher…"
t("annotation_position", 2, 5); // "2 of 5"
tn("annotations_removed", 3); // picks annotations_removed_<category>, else annotations_removed
```

- `i18n(namespace)` reads `script[type="application/json"][data-gmd-i18n="<namespace>"]` on first call, parses it
  once and caches it per document and namespace. Missing block or invalid JSON: an empty dictionary (every lookup
  falls back to its key), no throw. A second block with the same namespace: `console.warn` once and the first block
  wins, so the result never depends on order.
- `t(key, ...args)` returns the translation, or `key` when absent, with placeholders filled:
  - `%s` and `%d` take the next argument in order; `%[n]s` / `%[n]d` take argument `n` (1-based), Go's explicit
    index syntax, so a translator can reorder (`"%[2]d sur %[1]d"`); `%%` is a literal `%`. The same strings work in
    Go templates through `printf`.
  - A missing argument renders as an empty string.
- `tn(key, n, ...args)` selects the plural form with `new Intl.PluralRules(lang).select(n)`, where `lang` is
  `document.documentElement.lang` (invalid or empty tag: the runtime default). For a category other than `other` it
  uses `key_<category>` when the dictionary has it, else `key`; then formats with `n` as the first argument.
- The helper returns plain text. Callers set `textContent`, or escape before building markup (`search.mjs` today
  interpolates labels into `innerHTML` unescaped; it must escape them).
- No other exports beyond what the modules need; `escapeHTML` stays in each module that has it.

### Plural variants and the server

`Bundle.T`'s variant rule generalizes from `_one` to every CLDR category suffix (`_zero`, `_one`, `_two`, `_few`,
`_many`): where the page language translates the general form but not the variant, `T` answers the key, so
`i18nStrings` omits the variant and the client uses that language's general form instead of the default language's
variant. The server never selects a plural form itself (no template counts), so no Go plural library is needed.

Variant strings carry the placeholder instead of a literal number, because several languages put more than one
number in a category (French `one` covers 0 and 1): `annotations_open_count_one: "Annotations (%d note)"`,
`annotations_removed_one: "%d note no longer matches this page and was removed."`.

### Module changes

- `code-copy.mjs`: becomes an ES module (`<script type="module">`), reads `i18n("code_copy")`. Module scripts run
  after parsing; buttons appear at the same moment the page becomes interactive, no visible difference.
- `search.mjs`: reads `i18n("search")`; the dialog's `aria-label` uses `search_label`, the input `search_query`, the
  results list `search_results`; labels escaped before `innerHTML`.
- `gmd-annotations.mjs`: `labeler` / `readConfig().labels` replaced by `i18n("annotation")`; `P` becomes `tn`.
  Its config block keeps only page data.
- `gmd-color-chip.mjs`: default `aria-label` from `t("color_chip_label", value)`.
- English fallback literals in the modules (`|| 'Copy'`) are deleted: the block is always emitted with its module.

### Template and theme changes

- `scripts-shared` emits each block inside the feature guard of its module (`code_copy`, `search`, `annotations`,
  `color_chips`).
- `default.html.tmpl` and `error.html.tmpl` drop every `data-*` attribute from `<html>`.
- The seven downloadable themes need no change; they gain localized search and copy buttons.
- `gomddoc-website`'s marketing theme does not call `scripts-shared`: it drops its eleven attributes, emits the
  `search` and `code_copy` blocks itself, and its own inline copy script (`marketing-shell.html.tmpl`, reading
  `data-copy-label`) reads `code_copy` through the helper.

## Testing

- **Vitest** (`web/unit/i18n.test.mjs`) on `gmd-i18n.mjs`: lookup and key fallback; `%s`/`%d` in order, `%[n]d`
  reordering, `%%`; `tn` with `en-US` (1 → `_one`, 0 and 2 → general), `fr-FR` (0 and 1 → `_one`), `ar` (`_few`,
  `_many`, missing variant → general); missing block, invalid JSON, duplicate namespace (warns once, first wins);
  invalid `lang`. The existing annotations tests move from `labels` objects to blocks in the test document. Vitest
  resolves `/_assets/gmd-i18n.mjs` through a `resolve.alias` in `vitest.config.mjs`.
- **A key-drift test**: every literal key a shared module passes to `t`/`tn` exists in `en-US.yml`, and every key
  a namespace table above lists exists. A test, not a review checklist.
- **Go**: `i18nStrings` filters by prefix, omits untranslated keys and untranslated plural variants (all five
  suffixes), and its rendered block escapes a `</script>` translation; a rendered default-theme page carries one
  block per enabled module, none for a disabled one, and no `data-*` attribute on `<html>`; `Bundle.T` variant rule
  per suffix.
- **Playwright**: one test on a `fr-FR` fixture page: the copy button and the search dialog show the French strings
  from a site locale file, and the annotations header button too. Axe checks stay as they are.
- `UI_INPUTS` adds `cmd/gomddoc/assets/shared/static/*.mjs`, so a change to the helper runs the UI suite.

## Builder's latitude

- Internal naming beyond the public surface fixed here (`data-gmd-i18n`, `i18nStrings`, `gmd-i18n.mjs`, `i18n`,
  `t`, `tn`, the key names).
- How the renderer receives the key list (an option taking `[]string` or the bundle).
- Whether `code-copy.mjs` is rewritten in modern syntax while it becomes a module; keep the diff small.
