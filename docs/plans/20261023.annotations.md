# Client-Side Page Annotations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Readers select text in a gomddoc page, attach plain-text notes stored in `localStorage`, and copy every
note of the page as Markdown for an LLM harness.

**Architecture:** One shared ES module (`gmd-annotations.mjs`) inlined by gomddoc's own `scripts-shared` partial,
configured by a JSON blob that carries the page's repo-relative source path and localized labels. Themes only mark the
content element and add a header button. Highlights use the CSS Custom Highlight API; no DOM wrapping. Front-end tests
(Vitest, Playwright) live in `web/` and run from `make ci` only when their inputs' hash changed.

**Tech Stack:** Go (stdlib, html/template), vanilla ES module, Vitest + happy-dom, Playwright + @axe-core/playwright,
GNU make, GitHub Actions.

**Spec:** `docs/specs/20261023.annotations-design.md`

## Global Constraints

- Feature key `annotations` under `theme.features`, default `true`; env `GOMDDOC_SITE_THEME_FEATURES_ANNOTATIONS`.
- Storage key: `gomddoc:annotations:` + `location.origin + location.pathname + location.search`; value
  `{"v": 1, "notes": [{id, quote, prefix, suffix, offset, note}]}`; empty entry is removed.
- Context length: 32 characters each side. Re-anchor: exactly one match of `prefix + quote + suffix`, otherwise the
  note is stale and removed.
- Highlight name `gmd-annotation`; CSS custom properties `--gmd-annotation-highlight`, `--gmd-annotation-accent`.
- Theme contract: `data-gmd-annotatable` on the element wrapping `{{ .Page.Content }}`; `<button
data-gmd-annotations-toggle>` in the header; both only when `.Feature "annotations"`. No new template field used by
  themes.
- Every visible string and ARIA label is a key in `cmd/gomddoc/assets/locales/en-US.yml`.
- Vitest suite under 5 s; Playwright suite under 30 s including server start; Chromium via `channel: "chrome"` (the
  system Chrome, no browser download).
- Commits: `type(scope): summary`, with the session's `Co-Authored-By` trailer; `make ci` green before each commit.
- Agents run `make ci` and only the targeted slow tests named in their task; no agent runs a full slow suite beyond
  that.
- Third-party deps are test-only, pinned to exact versions, lockfile committed (D48).

## Review Focus

1. **Selection across inline markup** (bold, links, inline code inside a paragraph) must anchor and re-anchor: Task 3
   test `selectorFromRange spans inline elements`.
2. **Repeated passages** (same sentence twice, e.g. in a list) must stay anchored when the 32-char context differs and
   be dropped when it does not: Task 3 tests `anchor returns null on two matches` and `anchor distinguishes by
context`.
3. **Throwing `localStorage`** (Safari private mode, blocked site data) must not break the page: Task 3 test
   `createStore falls back to memory when storage throws`.
4. **Text injected by other shared scripts** (code-copy button label, heading-anchor `#`) must not shift anchors
   between the moment of creation and the reload: Task 3 test `buildTextModel skips injected UI`; Task 5 e2e
   `note in a heading section survives reload`.
5. **Markdown-significant characters in the quote** (`*`, `_`, backticks, `>` at line start) must not corrupt the
   export: Task 3 test `formatExport escapes the quote`.

- `SKIP_SELECTOR: string`: `.copy-btn, .heading-anchor, gmd-color-chip, .katex, .language-mermaid, .mermaid,
[data-gmd-annotation-ui]`. Implementer checks each class name against `cmd/gomddoc/assets/shared/*.mjs` and the
  renderer's heading-anchor markup and corrects it there, in this one constant.
- `buildTextModel(root: Element): {text: string, nodes: Array<{node: Text, start: number}>}`: text nodes in
  document order, skipping subtrees matching `SKIP_SELECTOR`.
- `selectorFromRange(model, range: Range): {quote, prefix, suffix, offset} | null`: `null` when the range is
  collapsed, whitespace-only, or either boundary lies outside the model (inside a skipped subtree or outside `root`).
- `anchor(model, sel): {start: number, end: number} | null`: exactly one occurrence of
  `sel.prefix + sel.quote + sel.suffix`, else `null`.
- `rangeFromOffsets(model, start: number, end: number): Range`
- `headingPath(root: Element, model, offset: number): string[]`: text of the nearest preceding `h1`–`h6`
  and each shallower ancestor heading level above it, outermost first.
- `groupByLine(items: Array<{id: string, top: number}>, tolerance: number): Array<{top: number, ids: string[]}>`:
  items sorted by `top`, consecutive items within `tolerance` px of the group's first item share a group.
- `formatExport(page: {title, sourcePath, url}, notes: Array<{headingPath, prefix, quote, suffix, note}>, labels):
string`: exact layout of the spec's "Export format" section; `labels` keys `exportTitle` ("Review notes"),
  `exportSource` ("Source file"), `exportPage` ("Page"), `exportIntro`, `exportTop` ("(top of page)").
- `escapeMarkdown(s: string): string`: backslash-escapes `\ * _ ` [ ] < >`and a leading`#`, `>`, `-`, `+`, or
`1.` after whitespace collapse.
- `storageKey(loc: Location): string`
- `createStore(storage: Storage | null, key: string): {persistent: boolean, load(): Note[], save(notes: Note[]): void,
clear(): void}`: every storage call in try/catch; first throw flips `persistent` to false and keeps an in-memory
  copy; `save([])` removes the key; `load` ignores entries whose `v !== 1` (returns `[]`).
- `init(doc: Document, win: Window): void`: returns at once when `doc.querySelector('[data-gmd-annotatable]')` is
  null. The module ends with `if (typeof document !== "undefined") init(document, window);` so the import in Vitest
  (no marker element) has no side effect.
